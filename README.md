# news

2週に1回、外の情報を集めて置く場所です。Claude(AI)が古い情報のまま答えないため、そして持ち主が外の情報から学ぶために使います。目的は「あなたと私が共に成長すること」です。

対になるリポジトリは [Yako-jwkf/test](https://github.com/Yako-jwkf/test) です。test には、Claude の設定・ミスの記録・ルールがあります。news には外の情報だけを置き、test には、そこで決めたこと・試したこと・測ったことを置きます。

## 読み方
- `issues/` の一番新しい号から読みます。号の名前は日付です(例: `2026-10-13.md`)。
- 号は、上から読む順番に並んでいます(2026-10-08 から)。
  1. **あなた向けの1件**(一番上の枠): IT に詳しくない読み手向けに、専門用語の説明をつけて書いています。
  2. **この号で分かったこと**: 大事なことを3〜5行で。それぞれに「test への影響」(test にとって何を意味するか)が付いています。
  3. **食い違い**: test に書いてあることと、外の情報が合わないもの。「一言で」と「test への影響」を読めば足ります。専門的な中身は「くわしく」の枠にたたんであります。
  4. **逆向きの結果**: test の方針と逆の結果が出た研究。形は食い違いと同じです。
  5. **読み物**: 記事・論評(3件まで)。
  6. **記録**: Claude Code の変更・研究と発表・開けなかったもの・実行の記録。全部たたんであります。
- **Obsidian で読む**: news のフォルダを、そのまま1つの保管庫(vault)として開く形を考えて作っています。囲み枠(たためる枠)と、号の先頭のプロパティ(日付・種類・期間・食い違いの数・タグ)は Obsidian で見やすく出ます。号と一覧のつながりは相対パスのリンク(`../topics/…`)なので、GitHub でも Obsidian でも開けます。GitHub では、たためる枠が開いたまま出たり、枠の印が文字で出たりすることがあります(未確認)。
- 印の意味:
  - **本文**: 元の文書を全部、または書いた範囲を読んだ
  - **要旨**: 論文の要旨(はじめの短いまとめ)だけを読んだ
  - **要約**: 検索結果などの、ほかの誰かが書いたまとめだけを読んだ
  - **二次情報**: 記事・論評・議論。事実やルールの根拠には使わない
  - **私の意見**: 号を書いた Claude の考え。研究で報告されたことではない
- 「調べてほしいこと」は `backlog.md` の「あなたからの依頼」に書きます(会話で Claude に言えば書きます)。
- 号の食い違いを test に取り込むときは、test の会話で「10-13 の号の食い違い D1 を直して」のように頼みます。取り込んだか・見送ったかは test の `docs/knowledge/news-decisions.md` に残ります。

## フォルダと決まり

```
news/
├── README.md        この文書
├── PROMPT.md        定期実行の指示の全文
├── sources.md       毎回見に行く先と、前回届いたか
├── backlog.md       持ち越すもの(あなたからの依頼・照合待ち・まだ読めていない資料)
├── issues/          号。1回に1ファイル
├── topics/          主題ごとの一覧。各行に元の号へのリンク
│   ├── agent-config-research.md   エージェント設定の研究(test から移した)
│   ├── intelligence.md            頭の良さ(AI と人)(test のブランチから移した)
│   └── claude-code-changes.md     Claude Code の変更のうち、関係する分野だけ
├── templates/issue.md   号の型
├── scripts/check_issue.py   号の書き方の点検
└── .github/workflows/check.yml   同じ点検を GitHub でも動かす
```

1. **号は、書いた後は直しません。** 誤りは次の号で訂正します。いつの情報かを、号の日付で追えるようにするためです(2026-10-08 の試しの号だけは、形を決めるために書き直しました)。
2. **topics のファイルを先に作りません。** 新しい主題はまず号の中だけに書き、2号続けて出たら、会話の中で topics にファイルを作ります。「その他」のファイルは作りません。
3. **名前は英小文字とハイフンにします。** 号は日付だけです。年ごとのフォルダは作りません(1年で26号ほど)。
4. **定期実行が書いてよいのは** `issues/`・`topics/`・`backlog.md`・`sources.md` の「前回届いたか」の欄だけです。`PROMPT.md`・`templates/`・`scripts/`・`.github/`・この README は、会話の中で一緒に直します。GitHub の点検は、題が「号:」で始まるコミットがほかの場所を変えていたら落ちます。
5. **ページや PDF を丸ごと写しません。** 短い引用と URL と取得日だけにします。

## 定期実行
- claude.ai の Routine(決まった時刻にクラウドで会話を自動で始める機能)で、毎週火曜の朝(日本時間 7:07)に動きます。
- 前の定期の号から13日経っていなければ、何もせずに終えます。これで2週に1回になり、1回失敗しても翌週に取り戻せます。
- 手順は `PROMPT.md` にあります。
