# 号 2026-10-08(試し)

> [!tip] あなた向けの1件: AI は「エラー」には気づくが、「もっともらしい間違い」は見逃しやすい
> AI のエージェント(AI が道具を使って作業を進める仕組み)に、道具の不具合をわざと混ぜた実験です(2026-10-07 の論文)。
>
> - 道具がはっきり「エラー」と返したときは、91.3% で気づきました。
> - 道具が、形は正しいのに中身が違う答えを返したときは、58.8% しか気づきませんでした。
> - 「毎回結果を確かめて」と指示を1行足しても、気づく率は変わりませんでした。
>
> 論文の結びは「AI は、エラーが来たかどうかには反応するが、返ってきた中身は見ていない」です。
>
> 私の意見: AI に「気をつけて」と頼むより、結果を別の方法で確かめる仕組み(例: 答えを別の道具で照らす)を用意するほうが確かだと思います。論文はこの方法を試していません。
>
> - 試したモデル: Claude Haiku 4.5 など、3つの系統の6モデル
> - 続きを学ぶ入口: `/learn エージェントの失敗の見つけ方`

### D1 Claude Code の説明の一部が古くなっていた
- 一言で: Claude Code の「フック」(決まった場面で自動で動く点検)のうち、AI に「通すか止めるか」を判定させる種類(prompt 型)に、新しい返事の仕方と設定が1つずつ増えていた。test のナレッジは前の説明のまま
- test への影響: test のフックは7つとも別の種類(command 型)なので、動きは変わらない

> [!note]- くわしく
> - test の記述: `claude-code-config-spec.md`「prompt フック(AI に判断させるフック)は `ok`・`reason` を返すだけ」「Stop で `ok: false` を返すと、`reason` が Claude に戻って作業が続く」
> - 外の情報: 返す形は `ok`・`reason`・`impossible` の3つ。Stop・SubagentStop で `impossible: true` を一緒に返すと、理由を戻さずにターンを終える。設定に `continueOnBlock` もあり、PreToolUse・PostToolUse・TeammateIdle では `ok: false` でもターンを終えずに理由を戻せる
> - 変わらないこと: UserPromptSubmit は今も `ok: false` でターンが終わる(「発言の判定には使えない」という結論はそのまま)
> - 出どころ: [Hooks reference](https://code.claude.com/docs/en/hooks.md)(2026-10-08 に読んだ) ・読んだ範囲: 本文(prompt フックの設定の表と Response schema の節)

- test への影響: 私の意見では、方針はそのままでよい。test の根拠の書き方(「成功率が下がる」)を直すかどうか

> [!note]- くわしく

> - 照らし合わせられなかったこと: 「+4%」という数字は、第1版・第3版どちらの要旨にもない

## 逆向きの結果(test の方針と逆の結果が出た研究)

### 手順書に「このコマンドを実行する」と名指しのルールを足すと、AI がその手順を守る率が上がった
- 一言で: スキル(AI 用の手順書)の改訂を調べた研究。確かめられるルールを足すと、AI がその手順を守る率が平均 0.23(23 ポイント)上がった。効いたのは、コマンドや場所を名指しするルール
- test への影響: test は「ルールは『〜するな』の形で書く」方針なので、向きが逆。ただし、この研究は禁止の形のルールをあまり試していない

> [!note]- くわしく
> - 研究: Agent Skill Evolution: How Revisions Affect Coding Agents
> - 報告: スキル(SKILL.md)の改訂で、自動で確かめられるルール(例「run allium check を実行する」)を足すと、4つのエージェントで求めた操作をする率が平均 +0.23、正しさが平均 +0.10(3つのエージェント)上がった。効いたのは主に、前の版になかったコマンドやパスを名指しするルール。スキルの本文を必要なときだけ読む形では、伸びの約半分(51%)が残った
> - 当たる test のルール: `agent-config-research-2026.md` の「ルールは『〜するな』の形で書く」と、その根拠の Guardrails Beat Guidance(2604.11088)「害になったルールはどれも『〜しろ』型」。`mistakes.md` の「説明書を増やすと成功率が下がる」とも向きが逆
> - 論文自身の断り: 文字列で採点できるルールだけを選んだので、禁止のルールや条件つきのルールは少ない(禁止は22%)。モデルは推論なしで、1つ前の世代が中心
> - 試したモデル: 開いたモデル16個、Claude Sonnet 3.5・3.7・4.5、Claude Haiku 4.5、GPT-5.5(推論なし)。サンドボックスでは Qwen 3.5-9B・27B、Devstral-Small-2507、Claude Sonnet 4.5
> - 出どころ: [arXiv 2610.04832](https://arxiv.org/abs/2610.04832)(2026-10-04) ・読んだ範囲: 本文(要旨・モデルの節・妥当性の節)
